Keep secrets out of your code — and out of your coding agent.

Kimen is a small local vault plus a projection step. Your repository describes the runtime shape without containing secret values. Kimen supplies them only when a trusted process starts — or keeps them to itself while completing an approved operation for an agent.

Describe the runtime shape. Keep the values elsewhere.

In a .kmap, the left side is what the app sees. The right side is a key Kimen resolves from the local encrypted vault. The map is safe to commit because it contains no secret values.

The app sees ordinary environment variables and file paths. It does not call Kimen or know about the vault.

Let the agent request the outcome. Keep the credential in Kimen.

Moving a credential to another vault does not help if the agent can still fetch it. Kimen uses the credential itself and returns only the result.

The protected local binding defines the operation, its target and its accepted inputs. The project can request that operation, but it cannot redefine it or gain the broader authority behind it.

Where does your agent stop?

Kimen closes the gap when a repeated, specific task is blocked by a credential that grants far more power than the task requires.

The agent can ask. Only you can decide what that request means.

The repository may name a secret or operation, but it cannot create a credential, change the target or replace the approved operation with arbitrary code. Those decisions live in the protected local binding.

For a trusted app, the important boundary is before it starts: Kimen supplies the environment variables and files it expects. When an agent only needs an outcome, that boundary stays closed — Kimen keeps the credential and performs the operation.
