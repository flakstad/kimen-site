Secrets don't belong in the project your agent can read.

Your app still needs database passwords, API keys and service credentials. Kimen keeps them in a local encrypted vault, outside the workspace, and supplies them directly when your application starts.

Several runs ahead?Open the vault for a short, bounded session, then lock it again.
kimen session start --ttl 15m kimen session lock

The agent can start the app without a .env file.

The agent can inspect the code and .kmap, make changes and invoke the same kimen run command you use. Kimen resolves the values after invocation and passes them directly to the child process.

The secret does not need to appear in the workspace or the agent's prompt. The child process does receive it: if the program prints a secret, it can still appear in command output or logs.

Start with one secret.

Move it out of the workspace. Keep the app unchanged. Let Kimen provide it only where it is needed.
