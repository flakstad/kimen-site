A deployment credential gives the agent more than deploy-staging(…).

Even when the secret text is hidden from the model, a process using it may perform every operation that credential permits. Kimen gives the agent only the action you chose.

Pass the deployment credential to a process

That process can attempt anything the credential allows.

  • The credential is present in the process
  • The process chooses which provider request to make
  • A mistake can affect more than staging

Let Kimen perform deploy-staging(…)

Kimen accepts only a revision for the configured application and staging environment.

  • The agent never receives the credential
  • Application, deployment job and environment are fixed
  • The agent gets status and a receipt

You configure deploy-staging. The agent can call it, but cannot redefine it.

The application, deployment job, environment and credential stay in trusted Kimen configuration outside the agent-editable project.

The agent calls

deploy-staging(revision: "8d2f74a")

It can choose the revision. It cannot choose another application, deployment job or environment.

Kimen checks and runs

Application: acme/app. Job: deploy-staging. Environment: staging.

Kimen verifies the revision, adds the deployment credential and makes the fixed provider request.

The agent gets “deployment started.” It never gets DEPLOY_TOKEN or general provider access.

Use the same pattern for other jobs you still do manually.

Kimen must know the exact service and request it is allowed to perform. It does not run an arbitrary shell command with a secret attached.
