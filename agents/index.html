Your agent finishes the code. You still deploy staging yourself.

Not because deployment is difficult. Because the agent would need a credential that can do far more than deploy one revision to staging. So the autonomous work ends and you take over.

The application, deployment job, environment and credential stay in trusted Kimen configuration outside the agent-editable project.

The agent calls

Kimen checks and runs

Application: acme/app. Job: deploy-staging. Environment: staging.

Kimen verifies the revision, adds the deployment credential and makes the fixed provider request.

The agent gets “deployment started.” It never gets DEPLOY_TOKEN or general provider access.

Use the same pattern for other jobs you still do manually.

Kimen must know the exact service and request it is allowed to perform. It does not run an arbitrary shell command with a secret attached.
