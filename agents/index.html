A narrower boundary—not magic isolation.

Kimen Actions are intended to prevent secret disclosure through Kimen and limit a caller to selected operations. They do not promise that a fully compromised operating-system account can never steal credentials.

For stronger threat models, use the same narrow Actions across a sandbox, separate identity, container or remote broker. Kimen can provide the controlled bridge without pretending to be the isolation layer.

One developer can define an Action. A team needs to govern them.

Let agents and workflows do useful work without every developer inventing separate credentials, wrappers and security rules.
