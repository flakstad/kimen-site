Kimen Actions is a planned extension to Kimen Core.

Credentials are a poor interface.

A credential is usually a bundle of permissions. Give it to someone who only needs to deploy staging, and they also receive every other operation that credential permits.

Now the credential must be copied to their machine, kept out of Git, hidden from local processes, rotated when it leaks and revoked when access changes.

Often, nobody needed the credential itself.

They needed permission to do one job.

Alice may deploy staging. She does not need direct access to the deployment token.

Her project can name the operation it needs. Alice chooses whether to unlock it. Kimen uses the stored credential to perform that fixed deployment and returns the result.

The access Alice needs

deploy-staging(revision: "abc123")

The access she does not need

GITHUB_TOKEN=••••••••

Alice can deploy a revision to staging. She cannot turn that permission into another provider operation, reveal the token or pass it to a different process.

Define what may be done. Bind how it is done locally.

The project carries portable names such as deploy-staging. Each environment keeps the provider details, restrictions and credential under local control.

The project declares

deploy-staging(revision)
inspect-logs(service, since)

Names and accepted inputs. Safe to share with the project.

The environment binds

deploy-staging
  deployment: known workflow
  environment: staging
  credential: local

The fixed operation and its authority. Kept outside the project.

This extends the Kimen model already in use.

DATABASE_URL resolves to a value for a trusted process. deploy-staging(revision) resolves to an effect without revealing its credential.

Some requirements resolve to values. Others resolve to actions.

The Action names and syntax shown here are illustrative, not final CLI or API design. Actions and Action-only sessions are planned; today's Kimen sessions unlock vault use for the user's Kimen operations.

One operation can serve people, automation and agents.

The caller changes. The permitted job—and the credential kept behind it—does not.

Developer

Alice deploys staging without receiving general access to the deployment token.

CI

A release job publishes one artifact without receiving a general-purpose provider token.

Coding agent

An agent inspects recent logs or restarts a known staging service without cloud or observability credentials.

Define access once. Govern it across the team.

Local Kimen can remain useful and open source. Teams pay for coordinating who can perform which operations across developers, CI, workflows and agents.

Narrower access, not magic isolation.

Kimen Actions are intended to prevent secret disclosure through Kimen and restrict callers to selected operations. A fully compromised operating-system account is a stronger threat model; use sandboxing, separate identities or remote execution when that boundary is required.
