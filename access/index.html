Give access to operations, not credentials.

A developer, CI job or agent usually needs to deploy, inspect or restart something. They do not need to hold the credential to your infrastructure. Kimen keeps the credential and provider setup behind a small set of named operations.

Named operations are a planned extension to Kimen Core.

Stop copying the same credential to every place work can start.

Every copy creates another place where broad access must be stored, protected, rotated and eventually revoked.

The credential is not the job.

A deployment token is only the mechanism. The job is to deploy one revision to staging.

Give someone the token and they receive every operation it permits. You must copy it to another laptop or workflow, keep it out of Git, protect it from every process there, rotate it when it leaks and revoke it when access changes.

Most of that disappears when you share the operation instead.

Make the useful thing callable. Keep everything behind it private.

Kimen separates the operation a project needs from the environment-specific authority that makes it work.

The project names the operation

deploy-staging(revision)

The name and accepted input can live with the project. It contains no credential and no provider-specific implementation.

The environment controls the operation

A local Kimen binding fixes the staging target, deployment workflow, accepted revisions and credential. The caller cannot replace them with another command.

The caller receives the result

Deployment 8472 started

Kimen performs the operation. The caller receives its status—not the token, SSH key or general provider access.

The need belongs to the project. The authority belongs to the environment.

This is the same Kimen model, extended beyond values.

Kimen already lets a project name the runtime configuration it needs while each environment supplies the actual values locally.

deploy-staging(revision)

Resolves to an operation

Kimen uses the credential itself and returns the result without revealing it.

Use the same model for other narrow jobs.

Each operation has a fixed implementation, a small input space and a result the caller can safely receive.

inspect-logs(service, since)

Inspect one service and time window without distributing the observability credential.

restart-staging(service)

Restart a known staging service without giving the caller SSH or general cloud access.

trigger-backup(database)

Trigger one known backup procedure without handing out database administration access.

Not an arbitrary shell with a secret. Kimen controls the implementation behind every operation.

One operation. Every caller. One place to govern it.

Without a shared model, every developer and workflow accumulates its own credentials, wrappers and security rules.
