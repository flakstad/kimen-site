Move secrets out of your project.

Store database URLs, API keys and private files in Kimen instead of .env. Start your application with kimen run. The app gets the values it needs; developers, tools and agents do not need them sitting beside the code.

.gitignore keeps a secret out of Git. Not out of your workspace.

Any editor, script, tool or coding agent with file access can read an ignored .env, private key or service-account file.

The value sits beside the code

A plaintext file contains a reusable credential that any permitted local process can read.

A read secret cannot be unread

Keep using environment variables. Stop storing them in .env.

Your application does not need a Kimen library. Kimen stores the values and supplies the same environment variables when you start the app.

Store the value locally

Kimen prompts for the value without putting it in shell history or a plaintext file.

Map it to an environment variable

This file contains only the environment-variable name and the Kimen secret name, so it can stay with the project.

Start the application

Kimen reads the map and sets DATABASE_URL for ./app. Nothing is exported to the rest of your shell.

Use the same stored values without copying them into every tool.

Pass secrets to a local application or test, render a file for a program that requires one, or generate an envfile for a process manager.

Run an application

kimen run --profile dev -- ./app

Run a test suite

kimen run --profile test -- ./test

Render a required file

kimen render --dir ./runtime --profile staging

Prepare an envfile

kimen envfile --out .env.runtime --profile worker

The selected process receives projected values. Use kimen run for software you trust with those values—not as a sandbox for arbitrary code.

Most people need an action—not the credential behind it.
