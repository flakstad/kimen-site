Local-First Secrets Projection

Latent capabilities, expressed on intent.

Kimen stores secrets securely at rest and projects them into runtime form only when explicitly requested, as env vars, rendered files, or scoped execution contexts.

Secrets remain inert by default. Runtime exposure is brief, specific, and intentional.

The Runtime Model

1. Latent

Secrets are encrypted at rest and not materialized by default.

2. Projection

Intent requests a specific runtime shape: env, file, or process scope.

3. Bounded Lifetime

Projected material is scoped and short-lived, then cleaned up.

Why The Name “Kimen”

In Norwegian, kimen points to an incipient form: the first stage from which something develops. In botany, biology, chemistry, and figurative use, it captures the beginning state where growth becomes possible.

That maps directly to Kimen’s model: secrets already contain capability, but in latent form. They only become runtime-real when intent is expressed.

Current Scope

What Kimen is now

  • Local encrypted vault.
  • Intent-driven runtime projections.
  • Team sync with conflict-aware orchestration.
  • Machine-readable CLI contracts and typed exit codes.

What it is not (yet)

  • No mandatory hosted backend for runtime use.
  • No required signup to use the product.
  • No central plaintext secret execution model.
  • Hosted coordination remains optional and undecided.
