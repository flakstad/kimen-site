local-first secrets for code and coding agents

Keep secrets out of your code — and away from your coding agents.

Your project can still declare exactly what it needs. Kimen keeps the actual values in an encrypted local vault and provides them only when a runtime needs them.

Install Kimen, create a vault and move one non-production secret into it. You can keep using ordinary environment variables inside the application.

Install

brew install flakstad/kimen/kimen

Or download the latest release.

Store and run

kimen vault init
kimen secret set stripe_api_key
kimen run --profile dev -- ./your-app

Use a test or staging credential while evaluating the workflow. Read the five-minute setup for the profile file and the exact boundary.

What this boundary does — and does not do.

Kimen removes plaintext values from the repository and materializes them at runtime. A process that receives a projected secret can read it. If a coding agent controls that process, the process is not a trusted runtime merely because Kimen launched it.

An unrestricted agent running as your Unix user may also be able to read or invoke an active Kimen session. Keep the vault locked while an untrusted agent has broad shell access. Stronger agent-aware unlock, client controls and bypass diagnostics are being explored; they are not claims of the current release.
