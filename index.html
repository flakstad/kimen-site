local-first secrets for ordinary applications

Kimen is a local-first secrets tool.

Kimen stores secrets in an encrypted local vault and lets you project them into runtime only when you explicitly ask.

Applications are usually simplest when they read configuration from environment variables or files. Kimen handles secrets outside the application process and provides those values only at launch time. You avoid ad-hoc .env workflows, copied tokens, and long-lived shell exports. 

kimen run --env SERVICE_API_TOKEN=demo_service_api_token -- sh -lc 'echo "Token length: ${#SERVICE_API_TOKEN}"'

Install

Kimen is primarily used as a native binary named kimen. Install from the latest GitHub release, or build from source if you are already in the repository.

Release

Download the latest release artifacts, place kimen on your PATH, and verify the checksum before using it.

latest release

Build From Source

Building from source writes `target/kimen` and refreshes the local launcher under `~/.local/bin/kimen`. 

bb native
kimen version
kimen vault init

Examples

Use one secret for one process.

Map one vault entry to one env var for one child process instead of exporting it into the whole shell session. 

kimen run --env SERVICE_API_TOKEN=demo_service_api_token -- ./your-command

Render a file when a tool insists on a path.

Some tools need a file, not an env var. Render it only when needed and keep the secret out of long-lived config. 

OUTDIR="$(mktemp -d -t kimen-render.XXXXXX)"
kimen render --dir "$OUTDIR" --file service-api-token.txt=demo_service_api_token

Generate an envfile for a supervisor.

If a process manager wants `KEY=VALUE` input, generate it without printing secrets to the terminal. 

kimen envfile --env SERVICE_API_TOKEN=demo_service_api_token --out .env.runtime
