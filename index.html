Local-first runtime projection

Keep secrets latent until the command actually needs them.

Kimen stores secrets in an encrypted local vault, then projects them into runtime only on explicit intent. Not into every shell. Not into stray env files. Not into every tool that happens to be open.

See Real Examples Start With The CLI
  • Scoped runtime shapes: environment variables, files, envfiles, child processes.
  • Local runtime stays usable without a hosted control plane.
  • Team sync stays ciphertext-first instead of turning runtime into SaaS policy plumbing.

01

Field Manual

Who it is for

Built for engineers who want local runtime sovereignty without the usual secret sprawl.

Usual drift

  • Global shell exports that outlive the task
  • Copied `.env` files with unclear ownership
  • Runtime coupled to a hosted secret provider
  • Agent tooling inheriting secrets it never needed

Kimen is for developers, operators, and small technical teams that prefer explicit runtime boundaries over ambient secret availability. The value proposition is narrow on purpose: encrypted local storage, strong CLI contracts, and runtime projection when you actually mean it.

Local dev
Run a tool with one env var for one command, then let it disappear.
Automation
Generate files or envfiles only when an external tool forces that shape.
Agent workflows
Narrow the blast radius when an assistant only needs one projected capability.

02

Projection Recipes

Concrete examples

More useful than “secure your secrets.” These are the moments where secret sprawl usually begins.

One command, one env var

Local development without a global export

Map a vault entry to one child process and keep it out of the rest of the shell session. 

$ kimen run \
    --env SERVICE_API_TOKEN=demo_service_api_token \
    -- sh -lc 'echo "Token length: ${#SERVICE_API_TOKEN}"'

File-only tool

Render a secret with strict permissions

When a tool insists on a file, generate it just for that run instead of keeping a plaintext artifact around. 

$ OUTDIR="$(mktemp -d -t kimen-render.XXXXXX)"
$ kimen render --dir "$OUTDIR" \
    --file service-api-token.txt=demo_service_api_token

Supervisor-friendly

Generate an envfile for systems that expect one

Support process managers and CI wrappers without printing secret values back to the terminal. 

$ kimen envfile \
    --env SERVICE_API_TOKEN=demo_service_api_token \
    --out .env.runtime

Agent boundary

Give a coding assistant the one projected key it needs, not your entire shell context. 

$ kimen run \
    --env PROVIDER_API_KEY=assistant_key \
    -- codex

Ciphertext-first team work

Sync encrypted state without changing the local runtime model

Team coordination exists, but Kimen still treats runtime as a local concern instead of a mandatory hosted dependency. 

$ kimen sync preflight --json
$ kimen sync status --json
$ kimen sync push

03

Operational Contrast

Difference in practice

From ambient exposure to explicit projection.

Ambient pattern

Long-lived shell exports and copied env files keep secrets around after the task is over.

Kimen move

Project one variable or one file for one command, then remove it from the runtime surface again.

Ambient pattern

Hosted control planes become part of the runtime path even for local work.

Kimen move

The vault is local-first. Team sync is useful, but it does not redefine the runtime dependency model.

Ambient pattern

Every open process inherits whatever happens to be exported in the current shell.

Kimen move

Projection is named, scoped, and attached to intent. The blast radius of mistakes gets smaller.

Kimen reduces accidental exposure. It does not claim magic once you deliberately hand a secret to a process.

04

Current Scope

Positioning

Local encrypted vault now. Explicit runtime projection now. Team sync now. Mandatory hosted control plane, no.

What exists today

  • Encrypted local vault protected by a passphrase.
  • Projection into env vars, files, envfiles, and child processes.
  • Typed CLI output for automation and machine-readable workflows.
  • Encrypted team sync via `fs` and `git` remotes.

What Kimen is not trying to be

  • Not a browser-first secret management dashboard.
  • Not a required signup or hosted runtime dependency.
  • Not a central plaintext execution model wearing a security label.
