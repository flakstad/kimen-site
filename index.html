Local-first secrets CLI

Vault secrets locally. Project them into the process that needs them. Only when you ask.

Kimen stores secrets in an encrypted local vault, then materializes them as env vars, files, or envfiles at runtime. The point is simple: keep secrets out of ambient shell state and expose them only with intent.

It is not a hosted control plane. It does not pretend a process is safe after you deliberately give it a secret.

Model

One narrow idea: keep secrets out of ambient runtime state.

What Kimen does

  • Stores secrets in an encrypted local vault.
  • Projects them into env vars, files, envfiles, or child processes.
  • Keeps local runtime usable without requiring a hosted backend.
  • Gives automation structured CLI output instead of brittle text parsing.

What Kimen does not do

  • It does not make a secret safe after a process receives it.
  • It does not rely on global shell exports as the default.
  • It does not require a browser UI or an account to work.
  • It does not turn runtime access into a hosted policy problem.

Examples

Use the secret shape the tool requires. No more.

Env var for one process

Run a command with one projected secret.

Map one vault entry to one environment variable for one child process instead of exporting it into the whole shell session. 

$ kimen run \
    --env SERVICE_API_TOKEN=demo_service_api_token \
    -- sh -lc 'echo "Token length: ${#SERVICE_API_TOKEN}"'

File when a tool insists on a file

Render a secret with strict permissions.

Some tools only accept files. Generate the file when needed rather than keeping plaintext config around by default. 

$ OUTDIR="$(mktemp -d -t kimen-render.XXXXXX)"
$ kimen render --dir "$OUTDIR" \
    --file service-api-token.txt=demo_service_api_token

Agent or tool boundary

Project only the capability a tool needs.

If an assistant or subprocess needs one provider key, give it one provider key. Do not hand it the rest of your runtime state. 

$ kimen run \
    --env PROVIDER_API_KEY=assistant_key \
    -- codex

Scope

Current scope is practical and specific.

Encrypted local vault.

Explicit runtime projection into env vars, files, envfiles, and child processes.

Optional encrypted sync for team state.

Structured CLI output for automation.

Start

Start with the CLI.

Build from source, initialize a vault, and start with the smallest possible exposure surface. 

$ git clone https://github.com/flakstad/kimen.git
$ cd kimen
$ bb native
$ kimen vault init
