The right boundary depends on whether the caller needs the credential itself or only the result of using it.

Project to a trusted runtime

An application needs DATABASE_URL to connect. Kimen supplies the value through env, file or stdin when that process starts.

$ kimen run --profile dev -- ./app

The receiving process can read the value.

Invoke an action for an agent

An agent needs to deploy one revision. Kimen uses the credential inside a trusted adapter and returns the outcome.

$ kimen invoke deploy-staging \
    --revision 8d2f74a

The agent receives a result and receipt, not the credential.

The project may request authority. It cannot define or enlarge it.

The protected local binding fixes the operation, destination and permitted inputs. Editing the repository cannot replace an approved action with an arbitrary script.

Actions keep the underlying credential inside Kimen's adapter. Grants can be tied to a caller and time window, and every attempt produces a receipt.

Projection remains a deliberate trust decision. A process that receives a secret is inside the boundary and can read the value.
