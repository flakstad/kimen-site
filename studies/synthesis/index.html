Keep secrets out of your code — and out of your coding agent.

Kimen keeps values and external authority behind a local boundary. Your project describes what it needs. You decide whether Kimen supplies a trusted runtime or performs a constrained action for an agent.

Keep plaintext secrets out of the workspace.

A committed .kmap lets people and agents see what the application needs. The actual values live in the local encrypted vault.

env DATABASE_URL=secret:database_url

Kimen passes the value only to the chosen process when it starts. That process can read it.

Delegate use of authority, not possession of it.

Moving a credential to another vault does not help if the agent can still fetch it. Kimen mediates the operation itself and returns only the result.

The protected local binding defines what the operation means, where it may run and which inputs are accepted. The project can request that operation, but it cannot redefine it.

The repository may name a secret or operation, but it cannot create a credential, change the target or replace the approved operation with arbitrary code. Those decisions live in the protected local binding.

When a trusted program genuinely needs a secret, Kimen projects it at runtime. When an agent only needs an outcome, Kimen keeps the credential and mediates the operation.
