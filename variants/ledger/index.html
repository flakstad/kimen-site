Kimen

Open source CLI
A local command-line tool for storing secrets in an encrypted vault and projecting them into environment variables or files for the process that needs them.
Type

Command-line tool

Storage

Encrypted local vault

Projection

Env vars, files, envfiles, child processes

Runtime model

Local-first

What it is

Plain language first.

Kimen keeps secrets out of ambient shell state. You store a value in the local vault. Later, when a command or tool needs that value, Kimen can inject it as an env var or render it to a file for that one use.

Problem

Secret values often spread through global shell exports, copied `.env` files, and tools that never needed them.

Kimen approach

Keep the value encrypted until you explicitly project it into the target process.

Why it exists

Storage alone is not enough. The more important question is how a secret enters runtime and how widely it is exposed on the way in.

How it works

Vault. Ask. Project. Run.

01

The secret is stored in the encrypted local vault.

02

You ask Kimen to map it to a name and a runtime shape.

03

The target command starts with that value available.

04

The secret is not left as general shell state by default after the command finishes.

Examples

Actual commands.

One process, one env var

$ kimen run \
  --env SERVICE_API_TOKEN=demo_service_api_token \
  -- sh -lc 'echo "Token length: ${#SERVICE_API_TOKEN}"'

Render a file when a tool requires one

$ OUTDIR="$(mktemp -d -t kimen-render.XXXXXX)"
$ kimen render --dir "$OUTDIR" \
  --file service-api-token.txt=demo_service_api_token

Give a tool one key, not the whole shell 

$ kimen run \
  --env PROVIDER_API_KEY=assistant_key \
  -- codex
