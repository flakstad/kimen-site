Kimen is a local-first secrets tool.

Kimen stores secrets in an encrypted local vault and lets you project them into runtime only when you explicitly ask. The point is not just storage. The point is controlling how a secret enters runtime and which process receives it.

Vault -> config -> env -> app

What It Is

A local-first CLI. Secrets stay encrypted at rest in the vault until you deliberately project them for one run.

How It Fits Config

Stable config can stay plain. The sensitive fields come from Kimen at runtime, so you do not need to spread secrets through copied files or long-lived shell exports.

What The App Sees

Nothing special. The app still reads normal env vars or files. The projection logic stays outside the application, because Kimen can prepare the runtime env up front.

Start a process with one secret env var:

$ kimen run --env API_TOKEN=assistant_key -- myapp

The application code can stay ordinary:

const apiToken = process.env.API_TOKEN;
